# M5: Coupling the Chemistry Layer to Agents. Heredity by Self-Copying Code

## Question
In Geb, heredity is a built-in operator: crossover plus one bit flip per birth. M5
replaces it with heredity done by the genome's own code. Each agent's genome is a byte
tape that is read in two ways:
1. **Phenotype.** The tape is unpacked to 8 genes per byte and decoded by Geb's unchanged
   developmental (L-system) decoder into the agent's neural network.
2. **Heredity.** At a birth, the tape is executed as BFF code (M3). The child receives
   whatever the code writes into a buffer.

The founders come from the M3 chemistry layer: replicators that emerged in BFF soups.
Behaviour still decides when a birth happens, through Geb's reproduce action. The
question is whether Geb-style evolution, and its unbounded activity, survives when
heredity is endogenous, and whether copy fidelity evolves under selection on behaviour.

## Prior work (survey, November 2026)
None of the individual parts is new. The closest precedents:

| Work | Overlap with M5 |
|---|---|
| Tierra (Ray 1991), Coreworld (Rasmussen et al. 1990), Amoeba (Pargellis 1996, 2001) | Heredity performed by the genome's own code. Amoeba: replicators emerge from random code. |
| Avida (Ofria & Wilke 2004); navigation and predation variants (Grabowski et al. 2008, 2013; Wagner et al. 2020) | The self-copying code also drives behaviour in a 2D world. |
| SwarmEvolve 2.0 (Spector et al. 2003, 2005) | Closest overall. Embodied agents whose own Push program builds the child's program; replicators arise in-world. |
| Nanopond (Ierymenko) | Heredity via what the code writes into an output buffer, as in M5. |
| Cicala et al. 2026, arXiv 2607.09211; Jha et al. 2026, arXiv 2609.10817 | Replication and function (arithmetic tasks; energy and cooperation) co-evolve in Z80 soups. |
| Knierim et al. 2026, arXiv 2607.01483 | BFF replicators are found just as easily by random mutation walks, which weakens how special the founders are. |
| SeRANN (Shvartzman & Ram 2024) | A neural network that copies its own genome; not embodied. |

**Apparently untested combination** (no instance found):
1. One tape that is both a BFF heredity program and the input to a separate developmental
   decoder for an embodied agent's neural controller.
2. Founders that emerged in a separate soup and were then transplanted into an embodied
   world.
3. Bedau-Packard evolutionary activity with a shadow null applied to endogenous heredity.

**Failure modes reported in prior work:**
- parasites and genome takeover (Tierra; Stringmol, Hickinbotham et al. 2021);
- replicators crowding out function, and genome shrinkage (arXiv 2607.09211);
- error thresholds and copy-fidelity collapse (Eigen; Wilke et al. 2001);
- autoconstructive stagnation (Spector);
- turnover waves that look like activity (arXiv 2406.19108).

## What failed first, and the design that came out of it
1. **Layout [parent 1 | buffer | parent 2], 192 bytes.** No founder copied itself (0%).
   - BFF replicators move their heads by wrapping off the end of the tape, so they
     depend on the exact tape length they evolved in.
2. **Native layout [parent | buffer], 128 bytes, exact-copy criterion.** Still 0% exact
   copies, because the M3 replicators copy fragments, not whole programs.
   - Measured over one generation (`tools/m5/fidelity.cpp`): 20-32 of 64 bytes are shared
     with the parent, at best alignment within ±8 positions; founder 5 shares only 8.
   - Over 20 generations (`tools/m5/lineage.cpp`), five founders keep a stable inherited
     region of 20-30 bytes, including their copy loop: 45-50 of 50 lineages are still
     copying at generation 20. Founder 5 loses copying in all lineages.
3. **Soup under the M5 protocol (`oee_bff -m5-protocol`).** Each child is only what the
   parent wrote, so no program persists unless it copies itself.
   - From random code, no copier arose in 2048 epochs; the soup stayed at high-order
     entropy 0. Whole-genome copiers do not appear spontaneously at this scale.
4. **The six M3 founder genomes inserted unchanged:** 0 births in 20,000 steps. Their
   decoded networks never trigger the reproduce action.
5. **Founders born rather than inserted.** Each initial agent is a child of a founder,
   produced by one application of the founder's own copy code. The population fills the
   world (about 380 agents), with about 80 births per step.

**Resulting design (M5 v1)**
- **Asexual, fixed length.** The genome is 64 bytes and the tape is [parent | random
  buffer of 64 bytes]. The parent's code runs as BFF and the child is the buffer.
- **Mate.** The mate triggers the birth but contributes no genes. With two parents' code
  acting on one buffer, the more aggressive copier would take over the child.
- **Mutation.** Background rate of 2^-12 per byte, as in the soup.
- **Partial heredity.** About a third to a half of the genome is inherited, including
  the copy loop; the rest is re-randomised at every birth.
- **Selection pressure.** Uncopied bytes still take part in decoding the neural network,
  so behaviour is only partly heritable. Selection on behaviour is expected to favour
  lineages that copy more of their genome. In the soup there is no such pressure.
- **Shadow nulls.** The shadow and second shadow breed with the same operator, so the
  null normalisation stays valid.
- **Integrity.** The built-in path is unchanged (`golden_equivalence` passes).
  `evaluate_n` equals the original 128-byte interpreter on 200,000 tapes. Coupled
  checkpoints carry their own magic number.

**Hypotheses**
- H1: inherited fraction rises over evolutionary time under BFF heredity with M3
  founders.
- H2: normalised activity grows relative to the null (Geb-style class 3), or fails to.
- H3: random founders, which have no working copier, show no heritable adaptation.

## Interim results (November 10, 2026)
`tools/m5/heritability.cpp`: for each agent, the number of informative (non-zero) genome
bytes that its own code passes to a child under the run's buffer rule. Best alignment
within ±8 positions, 8 trial births per agent. For random 64-byte genomes, chance
matching gives about 1.4.

| run | heredity rule | founders | outcome so far |
|---|---|---|---|
| m5_m3_s1 | v1: random buffer | M3 (born) | 9.9 inherited bytes at 80k steps, 8.0 from 160k to 800k; no agent copies ≥ 16 bytes; population fell from about 380 to about 200-270 |
| m5_rnd_s1 | v1 | random | froze at about 396k steps (no births for 100k); no rescue archive available |
| smoke test | v2: zero buffer | M3 and random | both collapse to blank genomes within 40k steps (0.01-0.02% one-bits); blank genomes reproduce in Geb, so "copy the blank" is a degenerate fixed point |
| m5v3_m3_s1 | v3: v1 plus viability (a child is born only if its own code passes on ≥ 16 informative bytes) | M3 (born) | 23.7 inherited bytes at 20k steps, then exactly at the threshold, 16.0, from 40k to at least 100k; world full (about 340-380 agents) |
| smoke test | v3 | random | no births in 40k steps; random code never copies |

**Readings so far**
- **H3 holds in every variant.** Without a working copier there is no heritable
  evolution: v1 froze, and v3 had no births.
- **H1 is not supported.** Heredity does not rise under selection on behaviour.
  - Under v1 it decays to a low floor of about 8 bytes, above chance.
  - Under v3 it falls straight to the imposed viability threshold and stays there.
  - So copying more than the minimum confers no measurable advantage in Geb's
    ecology at these time scales.
  - Explanation consistent with v1 and v2: Geb agents with random or blank genomes
    reproduce readily, so passing on behaviour-encoding bytes has weak fitness value
    compared with the cost of longer copying.
- **Known failure modes reproduced:**
  - copy-fidelity decay (error-threshold-like);
  - a degenerate replicator (blank genomes);
  - copying driven down to the minimum required. Compare the compact replicators
    produced under compute pressure in arXiv 2607.09211.

**m5_m3_s1 (v1) finished, 2M steps.**

**Heritability.** 7.3 informative bytes inherited at 2M steps. The series was
9.9 → 8.0 → 6.0 → 7.3, with copiers at 0% throughout.

**Activity** (`tools/activity/report.py`, second-shadow null):

| grouping | population | normalised median | normalised total | class |
|---|---|---|---|---|
| predecessor + link bits | real | 2 | 202 | 1 (no significant new activity) |
| predecessor + link bits | null | 2 | 15 | 1 |
| whole rule | real | 35 | 1607 | 2 (bounded) |
| whole rule | null | -4 | -43 | 1 |

Geb with built-in heredity, same configuration (M1): class 3b with predecessor + link-bit
components, normalised median 23-36 at 2M steps.

**Result.** With heredity performed by M3-derived BFF code (v1), Geb's unbounded
evolutionary activity is lost. With only about 6-8 of 64 bytes inherited per birth,
adaptations cannot accumulate. This is the error-threshold failure mode predicted by the
survey. v3 (viability rule) continues; its heritability is pinned at the 16-byte
threshold. Files: [results/m5/](results/m5/).

## Option A: engineered high-fidelity copier (m5v3_hifi2_s1, 2M steps)
**Founders.** 50 genomes, each laid out as follows:
- byte 0: the value 64, which acts as the copy counter (and is a no-op);
- bytes 1-51: random payload, excluding instruction bytes and zero;
- bytes 52-63: the copy code `<,[}-]>[.>}]`, which copies byte k to position k+64 for
  the whole genome.

The first variant put the copy code first and gave 0 births. That fixed prefix steers
Geb's decoder into brains that never reproduce. The run uses the v3 rules.

**Results**
- **Heredity:** 64.0/64 informative bytes inherited, from 20k to 2M steps.
- **Population:** about 350 agents at 25k steps, about 80-90 from 50k to 175k, then
  20-40.
- **Births:** nearly stopped.

| grouping | population | normalised median | class |
|---|---|---|---|
| predecessor + link bits | real | 8 | 2 (bounded) |
| predecessor + link bits | null | -4 | 1 |

**Reading.** Copy fidelity is not the only barrier. With perfect BFF copying, variation
comes only from background mutation: 2^-12 per byte, about 3% of children mutated. Geb's
built-in operator applies crossover, a bit flip and a length change at every birth. The
fixed 64-byte genome also removes Geb's genome growth. Unbounded activity therefore
needs heredity machinery that supplies variation and growth, not only fidelity. This
points to option C (separate copier and phenotype regions, with growth) or option D
(Geb's operator for the phenotype; BFF code governs birth). M5 is paused here. L3 is
next.
