# Evolved models: EGG and integer EGGROLL on CPU

Engine for the evolved brains of World v1 (docs/WORLD.md). These are models we evolve ourselves, never trained on
human data inside the system (PLAN.md §0).

## 1. Source

Sarkar et al., "Evolution Strategies at the Hyperscale" (EGGROLL), arXiv:2511.16652v2, ICML 2026. Our code is a
clean implementation from the paper text: Algorithm 2, Appendix G (architecture) and Appendix H (integer
EGGROLL). The authors' reference code (nano-egg) is GPL-3.0 and was not copied.

Facts from the paper that matter here (section 6.1, Fig. 2):
- **EGG.**
  - A 6-layer, width-256 recurrent byte model: a minGRU variant plus an MLP.
  - All weights are int8, with int32 accumulation and no activation functions; saturating int8 casts provide the
    nonlinearity.
  - It is trained only by evolution, with populations up to 2^20.
- **Result.**
  - EGG reached 3.40 bits/byte on MiniPile, against 3.58 for a backprop-SGD Transformer of the same size, on the
    same data per step.
  - The largest population used about 180 times the GPU-hours of the backprop baseline.
  - So evolution won on data efficiency and lost heavily on compute efficiency.
- **Update.**
  - Rank-1 antithetic perturbations, with sigma = 2^-4.
  - Fitness shaping is sign(s+ − s−).
  - A parameter moves one int8 step when |sum of F·A·B| exceeds 16·Φ^-1(1−α/2)·16·√P, with α = 1/(0.015t + 1).
  - α is about the fraction of parameters updated per step.

## 2. Code

- `src/evo/gemm.{hpp,cpp}`: int8 × int8 → int32 matrix multiply on Intel AMX tiles (TDPBSSD), K-blocked, with a
  scalar fallback.
  - Measured on this machine: 2.2 int8 TOPS per thread on raw tile operations, and about 5.5 TOPS on 4 threads while
    other work runs.
  - Our GEMM reaches 0.79 TOPS on one thread at 1024³.
- `src/evo/egg.{hpp,cpp}`:
  - EGG forward, batched over population rows, with per-row rank-1 noise on matrices, embeddings and vectors.
  - The noise is generated by counter RNG per (step, pair, parameter), so it does not depend on the thread count.
  - The integer update; checkpoints.
  - The integer layer norm uses exact floor division by multiply-shift, verified exhaustively.
- `apps/oee_egg/main.cpp`: byte-corpus trainer. Rows are persistent streams; both members of an antithetic pair read
  the same bytes. It logs train and validation bits/byte, the number of changed parameters, α, timings and MACs.
- `tests/evo/`:
  - GEMM against the reference, with 1 and 3 threads.
  - Weight-initialisation statistics.
  - The forward pass is identical across thread counts; zero noise equals unperturbed.
  - The update changes about α of the parameters (0.051 at α = 0.05).
  - Exhaustive check of the division.
- `tools/evo/backprop.py`: a numpy Transformer baseline with a hand-written backward pass, checked by gradient
  check. Off the critical path: comparisons on human text measure the wrong thing for our goal (PLAN.md §0).

## 3. Calibration on enwik8

Human text: this run only checks the engine.

- Model: 6L-256D, 4.86M parameters (matches the paper's formula 513D + L(4D + 12D²)).
- Training: population 1024, 16 sequences of 100 bytes per step, 2 threads at nice 5, about 3 s per step on the
  shared machine.
- Results: validation 5.22 bits/byte at step 50 and 4.79 at step 200 (log: runs8/egg_p1024_s1/log.txt). It is
  learning.

## 4. Stepping a subset of rows, and vector kernels

- `Stepper::step(obs, idx, m)` runs one step for only the m listed rows (compacted inputs and outputs), in chunks of
  256 rows so the buffers stay in L2. The other rows keep their recurrent state. World v1 uses it to step living
  agents only. Per-row results equal those of the full step (test_evo_egg).
- AVX-512 kernels for the per-row work. Each is bit-identical to the scalar code (test_evo_egg compares both paths;
  `use_simd(false)` forces scalar):
  - **layer norm:** the floor division as a 32-bit multiply-shift, exact for |x| <= 127², checked exhaustively;
  - **rank-1 noise:** the dot product and the fused int8 conversion;
  - **GRU gates** and the residual add.
- Speed at W1 sizes (D=64, 2 layers, one thread, machine shared with 4 runs):

  | Rows | Before | After |
  |---|---|---|
  | 4096 | 6.6 µs per row-step (16 GMAC/s) | 1.1 µs (93 GMAC/s) |
  | 512 | 6.0 µs | 1.4 µs |

- W0 and W1 logs are reproduced exactly by the new binary.
- What is left: AMX tile stores and the int8 conversion of the outputs, each about a fifth of the time.
