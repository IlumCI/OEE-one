# L4: co-evolving challenges (design)

Goal (DESIGN.md L4): pressure toward general problem-solving that comes from a changing environment, not
from scoring agents, so fitness stays endogenous. The owner's constraint from earlier discussion: a fixed
hazard only teaches agents to beat that hazard; the challenges themselves must evolve open-endedly.

Base world: v8 (growing world and neuron limit, kin colonies, colony reproduction, division of labour), the
configuration whose individual complexity kept rising to 5M steps. v9 showed earning space is not what drives
complexity, so L4 does not tie growth to collective births; growth stays on a schedule (or yoked), and the
new pressure comes from challenges.

## Prior work (arXiv check, 2026-11-18)

- POET (1901.01753) and Enhanced POET (2003.08536): environments and agents co-evolve; a child environment is
  kept only if it is neither too easy nor too hard for current agents (a minimal criterion band), and
  Enhanced POET keeps the most novel environments that pass it.
- Minimal criterion coevolution (MCC, the basis of POET): solvers must solve at least one maze; mazes must be
  solved by at least one solver. No fitness ranking on either side.
- Regret-based environment design (ACCEL, 2203.01302; TRACED, 2506.19997): curricula from agent regret. These
  score the learner and need a gradient-trained agent, so they do not fit endogenous fitness; noted, not used.
- Adversarial co-evolution with quality diversity (2505.06617): fixing one side caps open-endedness; both sides
  must evolve. Digital Red Queen (2601.03335): continual adaptation to a changing opponent in Core War.
- Known failure modes of co-evolution (Ficici and Pollack 1998, cited in 2601.03335): cycling and mediocre
  stable states. Countermeasures from POET: an archive of past challenges and novelty among challenges.
- Brain-body-environment co-design survey (2512.04770): POET-style loops as the reference framework.

## Mechanism: evolving locks on the land

Geb agents already act through prefix matching: an action fires when the summed activity of output nodes
whose character starts with that action's bit prefix exceeds a threshold. L4 reuses that machinery.

- **Locks.** Some cells carry a lock with a genome: a bit string (the key) and an effect. An agent can use a
  locked cell (move into it, or give birth into it) only if, at that moment, its outputs present the key:
  the summed activity of its output nodes whose character starts with the key exceeds the threshold, exactly
  as for an action. Nothing is scored; an agent that cannot open a lock simply cannot use that land.
- **What locks guard.** New land from world growth arrives locked, and locked cells are fertile (a birth
  there is cheaper or more likely). Opening locks therefore matters for reproduction, the only fitness.
- **Locks evolve (minimal criterion band).** Each lock counts how many distinct agents opened it over a window.
  A lock opened by at least one agent but by less than a set share of the local population reproduces into a
  neighbouring cell with a mutated key (bit flip, insertion, deletion: keys can lengthen). A lock nobody opens
  for long decays to open land; a lock everyone opens dissolves (it is no longer a challenge). Challenges thus
  track the edge of what agents can currently do, on both sides, without a fitness function.
- **Archive and novelty.** Dissolved locks enter an archive; new land occasionally receives an archived key,
  and among locks that pass the band, those with keys least similar to existing ones reproduce first. This
  counters cycling and the mediocre stable states of plain co-evolution.

## Staged plan

1. **L4a, static key locks.** Locks with fixed random keys, and the minimal criterion band as above. Measures:
   share of land opened over time, key length of the locks still being solved, agent complexity.
2. **L4b, temporal keys.** A key becomes a short sequence of patterns that must be presented over consecutive
   updates. This requires memory in the network and is the first step from pattern matching toward computation.
3. **L4c, cooperative locks.** A lock that opens only when two adjacent agents present two different keys at
   once. This ties L4 to the collectives: coordinated, role-differentiated groups open what individuals cannot.

## Controls

- **No locks** (v8 as is): baseline complexity and diversity.
- **Frozen locks**: locks exist but never evolve, so a solved world stops posing challenges.
- **Random churn**: locks change keys at the same rate as in L4 but at random, not by the minimal criterion.
  This separates adaptive co-evolution from mere environmental change (the Red Queen null).

Primary measures: maximum individual complexity and diversity against these controls (as for v8 and v9), plus
the evolution of the challenges themselves: key length and novelty over time, which should keep growing if the
challenge side is open-ended.

## Implementation sketch (Geb C++ port)

- `World`: a per-cell `Lock` (key bits, opener counts, age), saved in checkpoints; a lock population step at
  cycle boundaries (reproduce, decay, dissolve), with its own counter RNG stream.
- `Organism::try_to_move_forward` and `try_to_reproduce_with_organism_in_front`: before using a locked cell,
  test `action_output(key) > kTA` with the existing prefix-sum code.
- Locality: lock checks touch only the target cell, so the parallel engine's dependency rule is unchanged;
  lock reproduction runs at cycle boundaries.
- Flags: `-locks`, `-lock-band`, `-lock-frozen`, `-lock-churn`; logged per stats interval: locks, mean key
  length, share opened, archive size.
